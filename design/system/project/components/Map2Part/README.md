Proposal: the part level, where each try of one part is a row across the stations of the line, so the loop (build, check, sent back) and whether it is converging are both visible, with one step open below.

**Why this shape.** A retry sends a part back to Build carrying what still fails. Drawing each try as its own row under the same station columns makes the loop a return line, and puts the numbers that matter in one column: review blocking 5, then 2, now running. The selected cell (try 2 · review) opens below as three tiles: its most serious finding in the ink tile, the next finding beside it, and what the engineer claimed before that review with what you can do about it. There is no mini map: the header's crumbs and the zoom control already say where you are.

**Built on**: iterations and durations per try (`iteration_*` and `phase_*` events), verify counts (`verification_result`), blocking counts (`review_result`), findings with their try (`finding_recorded`), the engineer's per-story claims (`passes` in the part's `prd.json`), the decision this part came from (`decisions.json`, joined on `component`), `review.log`. Guidance goes into `scripts/kstrl/memory.md`, which is read at the start of every try (`factory.py:2673`), so try 4 would read it.
