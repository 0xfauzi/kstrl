Ask or do anything, over any level. A dialog (`role="dialog"`, `aria-modal="true"`) whose query is a combobox that keeps focus the whole time: the list is driven from it with `aria-activedescendant`, so rows never take focus.

**Markup**: `k-scrim`, then `k-cmd` holding three rows. The query row (`k-cmd-input`): the logo, `input.k-cmd-q` (`role="combobox"`, `aria-controls` the list, `aria-autocomplete="list"`, `aria-activedescendant` the active row) and an esc keycap; `k-cmd-context` names what an approval form is about. The body (`k-cmd-body`): the list (`k-cmd-list`, `role="listbox"`), sections (`k-cmd-sec`, `role="presentation"`) and rows (Row, `role="option"`), and beside it the detail (`k-cmd-detail`, `aria-live="polite"`): a head (`k-cmd-head`), text (`k-cmd-text`) and, under an answer, the records it came from as `measure` chips (`k-cmd-srcs`, `k-cmd-src`). The action bar (`k-cmd-bar`): on the left its note (`k-cmd-bar-note`), on the right the action ↵ runs (`k-cmd-act k-cmd-act-primary`, in `you`).

**Anatomy**: `radius-lg`, `shadow-window`, `window`. Query row 56px, 17px text, a `you` caret, a 2px `focus` underline while it has focus. List 340px (`--k-cmd-list`), 8px padding, scrolling on its own (`overscroll-behavior: contain`); the active row scrolls into view. Action bar 44px, 13px.

**Rows**: a question has a `?` mark; an action has its keys at the end, or, when it is unavailable, when it will be available (`aria-disabled="true"`, title stepped down to `text-2` at 500). An unavailable row stays selectable, so the detail can say why and the bar can name when; its action is shown unavailable, not hidden.

**What ↵ does**: the bar always names it. On an action, the action. On a question, where the answer is (Go to search-highlight, Open the approval), never something consequential: a question someone typed must not requeue a part. The note on the left says the consequence ("Nothing is saved until you save the note", "Opening it approves nothing") or the standing condition ("Answers come from the run records").

**Keys**: ⌘K opens it over any level, as the ask field does; pressed while it is open, it selects the query. Typing narrows the list and its sections (case and curly quotes ignored); the first match becomes active. ↑ ↓ move the active row and stop at the ends. ↵ runs what the bar names; a row's own keys (⌘G, ⌘O) run it from anywhere in the list. Tab moves between the query and the bar's action and never leaves the window. esc closes it; focus returns to where you were, or to the ask field when that is gone. Nothing matching: no active row, no action, and the detail says what to try.

**Pointer**: moving the pointer over a row makes it the active row (a still pointer under a window that just opened does not), so the list has one highlight, not a hover and a selection. A click runs the row and keeps the query focused. A click on the scrim closes it.

**Motion**: opens on `dur-enter`, `ease-enter`, from 98% and transparent; closes on `dur-exit`, `ease-exit`; the scrim fades with it. Reduced motion keeps both fades and drops the scale (`k-cmd-in-still`, `k-cmd-out-still`). The page under it is `inert` while it is open.

**The scenario, checked against kstrl**: the no-progress breaker fails a part at once rather than spend its last tries (`factory.py`, R7.5). `ks retry` resets the part and its cascade-skipped dependents, starts it from the base branch with its tries at 0 and re-enters `ks factory` under the launch record's limits, which needs `.kstrl/factory.lock`, so it waits for a live run to end. Guidance is a line under `## Guidance` in `scripts/kstrl/memory.md`, read when each part starts (`_run_component`), so running parts do not see it. `engineer.log` is the worker's transcript, appended across a run's tries. Cost by phase comes from `component_usage` events (architect, engineer, review, security, distill), and calls that reported no cost are counted, so the total is a floor.

**Don't**: add an "Actions" menu the keys cannot open; put a measurement among the source chips (write it in the text); let the bar's action run on a question.
