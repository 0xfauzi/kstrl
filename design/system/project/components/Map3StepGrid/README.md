Proposal, step level mode B (Grid): the run at a glance as tiles of different sizes, with the whole run in the large tile, one tile per working agent, and the latest thing a checker said given the widest tile.

**Why.** When you want everyone at once rather than one voice, size carries the hierarchy: the large tile answers "how is the run going" (agents working, the plan with the working parts lit, iterations, checks, sent back, spend counted); each agent tile answers "how far and what now" (a ring for iterations, or the check sequence for a checker, and its last line); the ink tile holds a checker's latest statement beside the plan decision it concerns, because a checker's words are where disagreement with the engineer first shows.

**Built on**: the manifest and plan for the graph; `iteration_*`, `phase_*` and `component_retrying` events for rings, checks and counts; `component_usage` for spend (counted when a phase ends); log tails for each agent's words, with the file's age; `decisions.json` (joined on `component`) for the decision.
